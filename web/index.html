  2. Dasselbe Firmware-Repository in VS Code öffnen.
  3. C-Code für Layout oder Anzeige bearbeiten.
  4. Die Datei speichern.
  5. Die aktualisierte Vorschau links beobachten.
  6. Unter „Beispielwerte“ Fahrzeugzustände verändern.
„Automatisch“ verwendet den aktuell ausgecheckten Branch einschließlich gespeicherter, noch nicht committeter Änderungen.

          
Wie funktioniert die Simulation?
Die Anwendung liest euren originalen C-Code und kompiliert ihn für diesen Computer. Hardwarezugriffe werden durch Host-Adapter ersetzt; CAN-Nachrichten und Taster sind simulierte Eingaben.
Display und LEDs zeigen das Ergebnis dieser ausgeführten Logik. Gespeicherte Codeänderungen werden etwa jede Sekunde erkannt. Die virtuelle Uhr läuft unabhängig von Browserabrufen. Eine Berechnung im C-Code muss nicht auf jeder Displayseite sichtbar sein.

          
Grenzen der Simulation
Dies ist keine vollständige Mikrocontroller-Emulation und keine echte Fahrzeughardware. Elektrische Eigenschaften, reale CAN-Kommunikation und Echtzeitverhalten werden nicht geprüft.
Eingaben ändern die laufende Sitzung. Nur Reset und Quellwechsel starten die Firmware neu. Die Vorschau garantiert kein korrektes Verhalten im Fahrzeug. Hardwaretests bleiben notwendig.

          
Windows: C-Compiler installieren

            
Am einfachsten: Im entpackten Projektordner Einrichtung_Windows.bat doppelklicken. Sie prüft Python und C-Compiler und installiert fehlende Komponenten nach Bestätigung mit J und Enter. Danach Start_Windows.bat verwenden.

            
Internet und Microsoft App-Installer (winget) werden für die Einrichtung benötigt. Falls winget fehlt, die Microsoft-App „App-Installer“ im Microsoft Store installieren/aktualisieren und erneut versuchen. Vorher alle MSYS2-/UCRT64-Fenster schließen. Eine vorhandene MSYS2-Installation wird bei fehlendem Compiler gegebenenfalls aktualisiert.

            
Die Einrichtung prüft am Ende eine echte C-Kompilierung und Ausführung. Die Firmware bleibt unverändert. Der normale Start lädt nichts herunter. Windows wurde hier noch nicht auf einem Windows-Rechner getestet.

    Es muss eine GCC-Versionsausgabe erscheinen.

„pacman nicht gefunden“? Den Befehl in MSYS2 UCRT64 eingeben. Die normale Windows-Eingabeaufforderung (cmd), PowerShell und das normale VS-Code-Terminal enthalten pacman üblicherweise nicht.

            
Optionaler Test in PowerShell:

Fehlerbehebung
Verzeichnis nicht gefunden: Unter „Quelle“ den lokalen Ordner mit DIC_23 erneut auswählen. Falls der Ordnerdialog nicht öffnet, den Pfad manuell eingeben.
Compiler fehlt: Auf macOS die Apple Command Line Tools installieren. Unter Windows die Anleitung „Windows: C-Compiler installieren“ hier in der Hilfe verwenden. Die pacman-Befehle gehören ins Fenster MSYS2 UCRT64; weitere Details stehen in der README.
C-Code kompiliert nicht: Unter „Quelle“ die vollständige Fehlermeldung öffnen, den Code korrigieren und speichern. Die Vorschau versucht es erneut.
Anzeige bleibt unverändert: Datei speichern, Quelle und ausgewählte Displayseite prüfen. Ein Git-Stand zeigt nur dessen committeten Code; für eigene Änderungen „Automatisch“ verwenden.
AMS-E bleibt OK: Diagnose und Firmware-LED sind getrennt: Ein Diagnosecode allein muss laut Firmware keinen LED-Ausgang setzen. Für den Text die reduzierte Seite wählen. CAN-Overrides können Eingaben überschreiben.
Verbindung unterbrochen: Das Startfenster muss offen bleiben. Nach einem Neustart die neu geöffnete Browserseite verwenden oder diese Seite neu laden.
